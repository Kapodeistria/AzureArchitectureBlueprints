# 📋 Canonical File Structure

## Overview

As of version 7.2.0, all case study analyses now generate **7 canonical files** with standardized names for consistent frontend display and user experience.

## Required Files

Every case study MUST generate these 7 files in the root output folder:

| File Name | Generated By | Description |
|-----------|--------------|-------------|
| `architecture-overview.md` | Architecture Design Agent | Complete Azure architecture design with diagrams, services, and integration patterns |
| `waf-security-analysis.md` | WAF Security Pillar Agent | Security pillar assessment with compliance status and recommendations |
| `reliability-assessment.md` | WAF Reliability Pillar Agent | Reliability pillar assessment with SLA and high availability analysis |
| `performance-optimization.md` | WAF Performance Pillar Agent | Performance pillar assessment with scalability and optimization recommendations |
| `cost-analysis.md` | WAF Cost Pillar Agent | Cost optimization pillar assessment with TCO and savings opportunities |
| `operational-excellence.md` | WAF Operational Pillar Agent | Operational excellence pillar assessment with DevOps and monitoring recommendations |
| `executive-summary.md` | Documentation Agent | Final comprehensive report combining all analyses |

## Implementation Details

### Dual Save Strategy

All agent outputs are saved **twice**:

1. **Timestamped File** (in `agent-reports/` subfolder)
   - Full audit trail with exact generation time
   - Preserves all historical versions
   - Format: `{step-name}-{timestamp}.md`
   - Example: `architecture-design-2025-10-01T14-30-22.md`

2. **Canonical File** (in root folder)
   - Standardized filename for frontend consumption
   - Always overwritten with latest version
   - Format: Fixed names from table above
   - Example: `architecture-overview.md`

## Benefits

### 1. **Predictable Structure**
Frontend can always find required files without checking timestamps or guessing filenames.

### 2. **Consistent UX**
All case studies display the same 7 files with consistent naming and icons.

### 3. **Demo Accuracy**
Real case study results match the demo structure exactly.

### 4. **Audit Trail**
Timestamped files in `agent-reports/` preserve full history for debugging and analysis.

### 5. **Blob Storage Compatibility**
Standardized names make blob storage listing and retrieval more reliable.

## Validation

To verify all required files are present:

```bash
# Check canonical files
ls output/case-study-*/
# Expected: 7 .md files with exact names above

# Check agent reports
ls output/case-study-*/agent-reports/
# Expected: 8+ timestamped .md files
```

## Migration

Existing case studies created before v7.2.0 will NOT have canonical files. To regenerate:

```bash
# Re-run analysis on existing case study
npm run analyze -- --case-study "path/to/original-case-study.md"
```

Or manually create symlinks/copies:
```bash
cd output/case-study-old/
ln -s agent-reports/architecture-design-*.md architecture-overview.md
ln -s agent-reports/well-architected-*.md waf-security-analysis.md
# ... etc
```
